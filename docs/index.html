También por npm y con un .deb. macOS, Linux y Windows.

Un medidor por cuenta arriba. El panel completo a un click.

Los monitores leen una credencial. Vos tenés tres cuentas.

Claude Code soporta varios perfiles con CLAUDE_CONFIG_DIR, y cada uno tiene su cuenta y su credencial. Un asiento de trabajo y una suscripción personal en la misma laptop es lo normal. Lo que existe lee una: la del directorio por defecto — que suele ser justo el que está vacío.

Todos los perfiles

Descubre cada CLAUDE_CONFIG_DIR de la máquina, no sólo ~/.claude. Y suma Codex y los proveedores que guarda opencode.

Sin credenciales

No abre tu llavero ni lee un token. El número sale de cachedUsageUtilization, donde Claude Code deja la última respuesta del servidor.

Y te avisa

Al cruzar el 80 % y el 95 %, cuando la proyección dice que chocás antes del reinicio, y —lo más útil— cuando te liberás.

El hallazgo que lo justifica

Dentro de limits[] hay barras que no tienen clave propia arriba. Leyendo sólo las dos famosas se veía una cuenta cómoda. La que realmente frenaba iba 67 puntos más arriba, con aviso del servidor.

five_hour — lo que leen los demás8 %
seven_day — lo que leen los demás59 %
weekly_scoped — la que te frena75 %

67 puntos de diferencia que se ven cómodos

Esa barra estaba marcada warning por el propio servidor y no aparecía en ningún monitor, porque no tiene una clave con nombre propio: vive adentro de la lista. quartermaster muestra la que frena antes, sea cual sea.

Donde ya estás mirando

El mismo número, dibujado para cada escritorio. No hay una app que abrir.

GNOME

Un medidor por cuenta en la barra, y el panel a un click con su extensión.

make indicador

macOS

La barra de menú, con el mismo panel y el mismo medidor.

make barra

Windows

La bandeja, con un anillo que dice cuánto queda. Anda desde WSL.

make tray

La terminal

Una tabla, o una línea para tu statusline. Y --json para scripts.

qm --breve

$ qm --breve
main 46/89%! · teams 36/60%! · codex 50/100%!
# sesión/semana por cuenta. «!» es una barra que el servidor marcó con aviso.

Instalar

No hay paso de compilación: qm lee el TypeScript directo, y por eso pide Node ≥ 22.6.

$ brew install legiosai/tap/quartermaster
$ qm
$ npm install -g @legios/quartermaster
$ qm
# el .deb está en la última release
$ sudo apt install ./quartermaster_0.1.2_all.deb
$ qm
$ git clone https://github.com/legiosai/quartermaster
$ cd quartermaster && npm install
$ make instalar   # deja `qm` en ~/.local/bin

El lanzador busca un Node que sirva en el PATH y en nvm; si no encuentra ninguno, lo dice y explica cómo conseguirlo.
